طريقة تحديث المشروع إلى Stage 7
================================

1) خذ نسخة احتياطية من Google Sheet قبل التحديث.

2) افتح:
Extensions > Apps Script

3) تأكد من إضافة الملفات الجديدة:
- Cache.gs
- Concurrency.gs
- Idempotency.gs
- IdempotencyRepository.gs

4) حدّث جميع ملفات Backend الموجودة في نسخة Stage 7، وليس الملفات الجديدة فقط.

5) اضغط Save.

6) شغّل:
verifyBackendInstallation()

يجب أن تكون النتيجة:
result = success
missing = []

7) شغّل:
setupSystem()

سيقوم بإنشاء ورقة نظام مخفية جديدة باسم:
_الطلبات

هذه الورقة لا تحتوي سجلات النفايات؛ هي فقط لمنع تكرار تنفيذ نفس الطلب.

8) شغّل:
runSelfTests()

النتيجة تظهر تلقائيًا داخل Execution log، بدون إضافة console.log يدويًا.
المتوقع:
passed = 13
failed = 0

9) انشر نسخة Apps Script الجديدة:
Deploy > Manage deployments > Edit > New version > Deploy

10) اختبر رابط Web App:
YOUR_EXEC_URL?action=health

المتوقع:
version = 7.0
contractVersion = 1.2

11) ارفع Frontend الخاص بـStage 7 أيضًا.

12) Smoke Test بعد النشر:
- تسجيل الدخول
- إضافة رحلة تجريبية
- التأكد من ظهورها في Google Sheet
- فتح سجل الرحلات
- حذف الرحلة
- التأكد من حذفها
- تحديث الإعدادات إن كنت مديرًا

ملاحظة:
Stage 7 لا يغيّر أعمدة بيانات النفايات الحالية. الإضافة الوحيدة في Google Sheets هي ورقة نظام مخفية خاصة بالـIdempotency.


ملاحظات Stage 7 النهائية:
- عند انشغال Lock، السيرفر يرجع BUSY والواجهة تعيد المحاولة تلقائيًا للعمليات الآمنة بنفس requestId.
- حفظ الإعدادات أصبح Write-First ثم تنظيف الصفوف القديمة، لتقليل خطر فقد الإعدادات عند فشل Google Sheets.
- استعادة كلمة المرور تعيد كلمة المرور السابقة تلقائيًا إذا فشل إرسال البريد.
- لا يوجد تغيير في أعمدة سجلات النفايات الحالية.
