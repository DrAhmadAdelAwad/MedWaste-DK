طريقة تشغيل MedWaste DK — Stage 8
=====================================

الإصدار: 8.0
API Contract: 1.3

1) خذ نسخة احتياطية من Google Sheet.

2) افتح:
Extensions → Apps Script

3) تأكد أن جميع ملفات Backend وعددها 29 ملف .gs موجودة داخل نفس مشروع Apps Script.
راجع:
BACKEND_FILE_MANIFEST_STAGE8.txt

4) اضغط Save.

5) شغّل:
verifyBackendInstallation()

المتوقع:
result = success
missing = []

6) شغّل:
setupSystem()

هذه الخطوة ستقوم تلقائياً بـ:
- إنشاء/فحص Sheets الأساسية.
- إنشاء Sheet مخفي باسم _سجل_التدقيق.
- تحويل Session Tokens القديمة الموجودة داخل _الجلسات إلى Hash آمن يبدأ بـ tok$.
- الإبقاء على بيانات السجلات والمستخدمين والإعدادات الحالية بدون تغيير أعمدتها.

7) شغّل:
runSelfTests()

المتوقع:
passed = 21
failed = 0

8) انشر Backend:
Deploy
→ Manage deployments
→ Edit
→ New version
→ Deploy

9) ارفع Frontend الخاص بـ Stage 8 في نفس نافذة التحديث.
مهم: Stage 8 غيّر القراءة المحمية من GET إلى POST لأسباب أمنية، لذلك لا تستخدم Frontend Stage 7 مع Backend Stage 8.

10) اختبر:
YOUR_EXEC_URL?action=health

المتوقع:
version = 8.0
contractVersion = 1.3
environment = production

11) يفضل تسجيل الدخول من جديد بعد التحديث.

12) Smoke Test:
Login
→ إضافة رحلة
→ التأكد من الحفظ في Google Sheets
→ مشرف/مدير يفتح سجل الرحلات والتقارير
→ المدير يحذف رحلة تجريبية
→ المدير يفتح admin_audit.html ويتأكد أن الأحداث ظهرت

مصفوفة الصلاحيات:
- مدخل بيانات: إضافة السجلات + قراءة القوائم.
- مشرف: ما سبق + سجل الرحلات والتقارير.
- مدير: كل ما سبق + الحذف + الإعدادات + المستخدمون + سجل التدقيق.

ملاحظة مهمة:
?action=health هو GET العام المقصود.
أما get_records / get_settings / get_users / get_me / get_audit_log فتم نقلها إلى POST محمي.
إذا جربتها يدوياً في رابط GET وظهر METHOD_NOT_ALLOWED فهذا سلوك صحيح وليس عطلاً.
